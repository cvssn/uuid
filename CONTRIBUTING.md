# como contribuir

patches e contribuições são absolutamente bem-vindas neste projeto

### dicas

commits devem ser formatados de acordo com a [especificação de commits convencionais](https://www.conventionalcommits.org)

sempre tente incluir um caso de teste. caso isto não seja possível ou necessário,
explique então o motivo disso na descrição da pull request

### lançamento

commits que irão precipitar uma mudança semver, como descrito na especificação
de commits convencionais, será alertado [`release-please`](https://github.com/cvssn/release-please-action)
para criar uma pull request candidata de relase. uma vez lançada, `release-please`
irá criar a release

para dicas de como trabalhar com `release-please`, veja a documentação

### requerimentos legais

em razão de proteger ambos, você precisará assinar a
[concordância de licença de contribuidor](https://cla.developers.google.com/clas)

você provavelmente já assinou isto para outros projetos google
